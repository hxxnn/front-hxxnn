# 글자 대비 자동 보정 (사용자가 색을 고르는 화면용)

사용자가 바탕·강조·사이드바 색이나 배경 이미지를 직접 고를 수 있는 화면에서, **어떤 색을 골라도 글자가 사라지지 않게** 하는 방법이다.
실제 서비스(support-assistant의 `public/theme.js`)에서 쓰던 방식을 일반화했다. 색을 고르는 기능이 없고 팔레트가 고정이면 `scripts/derive-palette.js`로 충분하다.

## 원칙

1. **사용자는 세 색만 고른다** (바탕, 강조, 사이드바). 카드·글자·보조 글자·테두리·연한 색조는 계산한다.
2. **보정은 명도만 움직인다.** 색조(hue)와 채도는 그대로 두고 HSL의 L만 한 칸(1%)씩 올리거나 내려 기준을 처음 넘는 값을 쓴다. 사용자가 고른 색의 인상이 유지된다.
3. **움직이는 방향은 배경이 정한다.** 모든 배경이 어두우면(명도 0.4 미만) 밝은 쪽부터, 아니면 어두운 쪽부터 찾고, 반대 방향도 시도한다. 끝까지 못 찾으면 흰색 또는 검은색.
4. **모든 배경 위에서 동시에 통과해야 한다.** 한 글자색은 카드 위, 바탕 위, (카드가 투명하면) 바탕에 번진 그라데이션 위에서 모두 기준을 넘어야 한다.
5. **보정했으면 사용자에게 알린다.** "강조 글자색만 어둡게 조정했습니다"처럼 무엇을 바꿨는지 한 줄로 보여 준다.

## 기준값

| 대상 | 기준 | 비고 |
| --- | --- | --- |
| 본문 글자 | 7 : 1 목표, 최소 4.5 : 1 | 카드·바탕 둘 다 |
| 보조·흐린 글자 | 4.5 : 1 | 투명 카드 위·바탕 위에서는 3 : 1까지 허용 |
| 강조 글자 | 4.9 : 1로 맞춰 두기 | 반투명 카드 위에서 4.5 : 1이 유지되게 여유를 둔다 |
| 막대·링·테두리 같은 글자 아닌 강조색 | 카드와 3 : 1 | 너무 비슷한 색을 골라도 사라지지 않게 |
| 컨트롤 테두리 | 카드와 3 : 1 | |

계산과 브라우저의 색 섞기는 0.05 안팎 차이가 난다. 검사 기준에 이만큼 여유를 둔다(4.5 → 4.58).

## 명도 보정 함수

```js
// 색조·채도는 두고 명도만 움직여 모든 배경(bgs) 위에서 대비가 min 이상이 되게 한다
function ensureContrast(color, bgs, min) {
  const ok = c => bgs.every(b => contrast(c, b) >= min);
  if (ok(color)) return color;
  const hsl = toHsl(color);
  const onDark = bgs.every(b => lum(b) < 0.4);
  for (const dir of onDark ? [1, -1] : [-1, 1]) {
    for (let step = 1; step <= 100; step++) {
      const c = fromHsl(hsl.h, hsl.s, clamp01(hsl.l + dir * step / 100));
      if (ok(c)) return c;
    }
  }
  return onDark ? '#ffffff' : '#000000';
}
```

`contrast`, `lum`은 WCAG 상대 휘도 공식이다(`scripts/derive-palette.js`에 같은 함수가 있다).

## 파생 순서 (이 순서가 중요하다)

1. 다크 여부: 흰 글자 대비 > 검은 글자 대비면 어두운 배경.
2. 카드: 어두우면 바탕을 흰색 쪽으로 7%까지 밝힌다. 단 흰 글자 대비가 5.2 아래로 내려가면 비율을 줄인다(경계 밝기 배경 대비). 밝으면 흰색 또는 바탕을 흰색 쪽으로 70%.
3. 본문 글자 → 보조 글자 → 흐린 글자 순으로 `ensureContrast`. 보조는 본문과 카드의 혼합(30%), 흐린 글자는 45%에서 시작한다.
4. 강조 글자색을 **카드 위에서 먼저** 정하고, 연한 강조 배경(soft)은 그 글자가 4.5 : 1로 읽히는 범위까지만 강조색을 섞는다(섞는 비율을 줄여 간다).
5. 글자가 아닌 강조 채움색은 카드와 3 : 1, 채움 위 글자는 흰색/검은색 중 잘 읽히는 쪽.
6. 사이드바 글자와 강조는 사이드바 색 위에서 따로 맞춘다.

## 유리·그라데이션 배경: 투명도 쪽을 보정한다

배경에 그라데이션이나 이미지가 비치면 글자색만 고쳐서는 부족하다. 이 경우 **글자색이 아니라 배경의 세기와 카드의 불투명도를 낮춘다.**

- 바뀌는 값: 그라데이션이 바탕에 섞이는 비율(`tint`), 카드 불투명도(`card`), 큰 면의 반투명도(`panel`).
- 후보를 **투명한 쪽부터** 줄 세운다. 예: `tint` 34 → 28 → … → 0 %, `card`는 20% 또는 55 → 70 → 85 → 100 %.
- 각 후보에서 배경 색 대표값마다 "보이는 색 = 바탕에 그라데이션을 `tint`만큼 섞고, 그 위에 카드색을 `card`만큼 얹은 색"을 계산하고, 글자 4종(본문, 보조, 흐린 글자, 강조 글자)이 기준을 넘는지 본다. **전부 통과하는 첫 후보를 쓴다.**
- 하나도 통과하지 못하면 그라데이션 0, 카드 불투명 100%로 되돌린다.
- 배경이 보이는 것이 먼저라서 배경 세기(`tint`)를 우선 지키고, 부족한 대비는 카드를 더 불투명하게 해서 채운다.
- 바탕 위에 직접 놓이는 보조 글자는 3 : 1까지만 요구한다. 그 이상 요구하면 배경 색이 거의 안 보인다. 카드 위 글자는 4.5 : 1을 지킨다.
- 읽을 글이 많은 큰 면(결과, 표, 문서)은 항상 모든 글자를 4.5 : 1로 지키는 가장 투명한 값(72 → 80 → 88 → 94 %)을 따로 고른다.

### 배경 이미지

이미지는 어느 부분이 글자 뒤에 올지 모른다. 업로드할 때 **밝기 대표값 5개**(밝기순 정렬 후 5%, 25%, 50%, 75%, 95% 지점의 색)를 뽑아 저장해 두고, 위 검사에서 `hues`로 쓴다. 이미지 진하기는 사용자가 정하되, 그 값을 **상한**으로 두고 그 이하에서 글자가 읽히는 가장 진한 값을 고른다.

- 이미지는 긴 쪽 1920px 이하 JPEG로 줄여 브라우저(IndexedDB)에만 저장하고 서버로 보내지 않는다.
- 화면의 CSP가 `img-src 'self' data:`이면 `blob:` 주소는 막힌다. 배경에는 `data:` 주소를 쓴다.
- **"이미지를 그대로 보기" 선택지**를 줄 수 있다. 켜면 바탕 위 글자 보정을 끄고 사용자가 정한 진하기를 그대로 쓴다(카드 안 글자만 지킨다). 글자가 안 보일 수 있다는 안내를 같이 띄운다.

## 결과를 CSS로 내보내는 법

- 계산한 색은 `<html>`의 인라인 CSS 변수(`--bg-card`, `--text-primary`, `--accent-text`, `--accent-soft`, `--gl-tint`, `--gl-card-pct`, `--gl-panel-pct` 등)로 넣는다. 지우면 CSS의 기본값으로 돌아간다.
- 색을 쓰는 CSS는 반드시 이 변수를 거친다. **하드코딩한 색은 따라 바뀌지 않는다.**
- 탭이나 구역마다 지역 변수가 있으면 `var(--cx-*, 기존값)`처럼 테마 값을 먼저 읽고 없으면 기존값을 쓰게 한다.
- 저장은 `localStorage`에 `{bg, accent, rail}` 정도만 하고, 읽을 때 `#rrggbb` 형식만 받는다(그 밖의 값은 버린다). `<head>`에서 먼저 불러 첫 화면이 그려지기 전에 적용해 깜빡임을 막는다.
- 바탕 밝기에 따라 `data-theme`을 자동으로 정하면 라이트/다크 전환 버튼 없이도 두 모드가 된다.

## 이 방식의 한계

- 대비 계산은 "카드색 × 불투명도 + 뒤 배경 × (1 − 불투명도)"라는 단순한 섞기 모델이다. `backdrop-filter`의 블러·채도 보정은 반영하지 않으므로 기준에 여유를 둔다.
- 이미지 대표값 5개는 근사다. 아주 대비가 큰 이미지에서는 국소적으로 글자가 읽히지 않을 수 있다.
- 구현 후에는 극단적인 색(아주 밝은 노랑 바탕, 거의 검은 강조색, 강조색 = 바탕색)으로 직접 확인한다.
